# Release validation

Velox 2.7.0 was reviewed using isolated application folders, phones and test desktops. Windows checks used an x64 Windows 11 host. Linux checks used Debian 12 under WSL with KVM, a regular account, isolated X11/Wayland desktops and an AlmaLinux 9 userland. These are application/profile tests on existing systems, not certification across every distribution, game or driver.

| Area | Evidence |
| :-- | :-- |
| Native code | All 16 modules passed GCC control-flow analysis at O0 without diagnostics. Additional optimized-analysis warnings were investigated, including a library exception-unwinding false positive. Review covered process identity, callbacks, resource lifetimes, background work and distribution boundaries. |
| Python | Compilation, Ruff checks and formatting passed. Security findings were reviewed individually, including validated archive extraction, subprocess arguments, private runtime paths and executable permissions. The packaged Python dependency advisory check reported no known advisories at test time. |
| Scaling and layout | 148,104 scaling cases and 37 orientation cases passed on Windows and Linux. Windows pages, setup, dialogs and native fields were checked at 75–300% in English/German: zero rendered-text overlap groups. Linux pages and maintenance views passed geometry checks at six requested scales. |
| Windows responsiveness | The final executable passed 917 window-message probes during movement, Android startup, live Android and System monitoring: 4.6 ms at the 95th percentile, 56 ms maximum. This measures launcher responsiveness on the test host, not game frame time or performance on other PCs. |
| Linux phone controls | X11 and Wayland passed real KVM display through OpenGL, rotation, mouse input reaching Android, closing/reopening the view without rebooting, worker cleanup and shutdown. Native capture was also checked independently on both display systems. |
| Root and navigation | Both platforms passed real Magisk preparation, rooted cold boots, guarded reverse-button installation and switching gestures/standard buttons, retaining shared SDK bytes. Shell access still requires the user's grant in Magisk. |
| Recovery | Linux backup verification, prepared activation/Undo, interrupted recovery, independent cold clones, storage moves/Undo, retention limits and owned-process cancellation passed. Earlier Windows controller, presets, recovery, removal and storage checks remain evidence for unchanged features. |
| File safety and updates | Actual NTFS checks covered hardlinks, held-file publication, resumed HTTPS downloads, checksum rejection and preservation of previous files. Linux signed metadata, tampering and cancellation checks passed. A real HTTPS AppImage update/restart test with a private future-version fixture retained the previous image and data, released the old launcher lease/socket, restarted and closed normally. |
| Regression tests | CI exercises signed HTTPS update download, progress and atomic publication using an ephemeral local key. Storage checks reject linked folders and filesystems that cannot enforce private permissions. Test keys and fixtures do not enter release assets. |
| Languages | Direct Linux UI labels and literal validation/status messages have German catalog coverage. Actual Qt standard buttons and decimal inputs follow language selection. Velox Home respects Android's 12/24-hour preference. |
| Setup and installer | Linux regular-account setup passed the license gate, verified cached Google packages, extraction, KVM denial and cold boot. Windows Google setup was validated in the earlier clean-profile run; current HTTPS/file handling was retested separately. The 2.7 installer passed English/German opening, fresh per-user install, exact payload checks, upgrade, launch and uninstall while retaining test preferences and phone data. |
| Public build | Fresh public sources rebuilt with new local Android signing material, without production keys, build caches, SDK copies or writable phones. |
| Distribution | The Windows ZIP passed 295 integrity, allowlist, resource and privacy checks and contains 15 files. Defender reported no threats in ZIP/installer with remediation disabled. Linux includes relative version/ABI/library inventories, complete notices and matching library/runtime sources. Permissions are normalized for safe extraction; SDKs, phones, credentials, caches and development records are excluded. |

The AppImage targets **x86-64 glibc 2.34+** with the GCC 11 C++ runtime and normal desktop graphics libraries. All 11 packaged pages passed in English/German in AlmaLinux 9. KVM and phone checks used Debian 12. Display-system checks used isolated Xvfb/TWM and Weston sessions with software graphics; these are not physical Linux GPU benchmarks.

Physical mixed-DPI monitor transitions, every controller, GPU/audio driver, distribution and game were unavailable for direct testing. Real resource checks have reached 32 online CPUs and 32 GB RAM; a true 64-CPU/64-GB guest remains unvalidated. Firmware changes and a WHP enable/reboot cycle were not repeated. Instant start is optional and off by default; its full snapshot lifecycle is not certified.

A clean scan provides evidence for the tested build and cases, not a guarantee of no vulnerabilities. Windows files remain unsigned with Authenticode; application update feeds remain cryptographically signed.
